# 分阶段开发计划

本项目先在网易客户端中验证底层接口与铁砧下落加工，再按阶段交付磁铁物流、电网流体和进阶生存内容；巨型铁砧、滑动结构与天体维度等高风险玩法先做独立原型实验，验证通过后再纳入发布范围。

本计划基于 2026-11-02 的上游源码调研制定，各玩法的实现方案与来源索引见 [migration-research.md](migration-research.md) 和 [sources.md](sources.md)。每个阶段的功能只有通过全部验收用例后才标记为已完成。每完成一个阶段，更新进度表并立即为该阶段单独创建一个 Git 提交。

## 阶段 0：平台与底层接口验证

在目标网易客户端中跑通最小行为包与资源包，逐项实测关键 ModSDK 接口的实际表现。

1. 确定目标客户端版本、基岩引擎版本、运行时 ModSDK 版本，以及 PC 端、移动端、单人存档、房主联机和联机大厅的支持范围，按需更新本地 `mc-netease-sdk` 补全包版本。
2. 在 MC Studio 中建立 `behavior_pack` 与 `resource_pack`，校验 `manifest.json`、固定包 UUID、Python 2.7 入口 `modMain.py` 以及服务端/客户端系统注册流程。
3. 实现测试用自定义重力铁砧，验证 `custom_heavy_block` 与 `netease:fall` 的开始下落、落地还原、破坏掉落事件；同时测试原版铁砧能否直接触发脚本事件并保留原版铁砧 UI。
4. 实测自定义机械元件的红石信号收发、`SetBlockNew` 方块替换、原版容器与自定义容器读写、物品 `userData` 传递，以及区块卸载重载时的 `CreateBlockEntityData` 持久化表现。
5. 验证客户端 UI 请求上报、服务端合法性校验与状态定向同步，制作适配手机触屏的操作测试界面。
6. 建立本地 `unittest` 测试入口与游戏内基准测试存档，记录空载场景的帧时间、脚本 Tick 耗时与存档体积，设定后续阶段的性能预算。
7. 复用原仓库的模型、贴图和音效，检查模型格式、朝向、UV 与透明材质在目标客户端中的表现。

验收标准：

- 行为包与资源包可正常导入、进入存档、退出并重新进入，服务端与客户端初始化日志清晰可查。
- 单次铁砧下落只结算一次。分别核对落入水中、落在半砖或切石机上、经过区块边界和下落中途卸载区块时的事件顺序与加工结果。
- 机器方块在放置、交互、区块卸载重载和退出重进后内部数据保持一致；带有耐久、附魔和自定义 `userData` 的物品存入容器再取出后数据无丢失。
- 产出完整的接口实测记录表，写明测试版本、复现步骤、实测结论与异常回退方案。

## 阶段 1：基础材料与铁砧加工

跑通从生存模式挖矿、查阅手册到手动操作铁砧加工产物的早期生存闭环。

1. 建立 Java 版与基岩版的物品、方块、标签与方块状态映射表，注册首批金属锭、装饰方块、矿石生成特征与基础合成配方，明确新存档生成与旧存档新区块的兼容方式。
2. 将上游工作台合成、熔炉烧炼与切石机配方批量转换为基岩版静态配方 JSON；单独登记带条件的模组联动配方与基岩版缺失的原版物品。
3. 实现服务端统一的铁砧落地事件监听、内存配方索引、下方加工平台校验、输入物品扣除与产物生成逻辑。
4. 接入首批方块粉碎、物品粉碎、物品压缩、方块压合、原版方块压榨、冲压和筛分配方；解包配方先支持普通物品，涉及容器内部物品数据的解包留到阶段 4 实现。
5. 实现基础版游戏内配方手册，展示加工所需的平台方块、输入数量与触发条件。

验收标准：

- 圆石→沙砾→沙子的方块粉碎链，以及 3 个骨头→1 个骨块的物品压缩配方在游戏内表现与上游一致。
- 双方块压合优先于粉碎，产物在下方格生成；炼药锅压榨按固体与流体一起结算，满锅、流体不兼容时保留原料。
- 每类加工均通过正常输入、数量不足、下方平台不匹配、多物品混合掉落、余量保留和同刻重复事件测试。
- 筛分按每份原料独立抽取各产物，生成失败后补发已抽中的物品，退出重进沿用这些数量。
- 连续两次铁砧下落、玩家贴近拾取与掉落物自然合并同时发生时，不会刷出双倍产物或吞没多余原料。
- 维护已落地配方的 ID 映射与验证清单，所有新增材料均可在生存模式获取并在手册中查到对应配方。

### 阶段 1 后续子任务

1. 方块涂抹代码已完成并通过自动化验证，共 122 条原版配方。保留催化方块、朝向与含水层，铜门上下半一起转换，游戏内表现待验收。
2. 四种专用加工台代码已完成并通过自动化验证。冲压平台可直接合成，五面改装消耗一件材料并保留库存，接入 89 条原版物品粉碎、装备回收和 5 条冲压配方。回收数量依照上游随机配方，顶面投取、自动收料、底部出料和拆除退款已回放验证，游戏内表现待验收。
3. 补齐基础材料、静态合成和阶段 0 的红石、容器、存档接口实测，再进入阶段 2 的磁铁循环与物流。

## 阶段 2：磁铁、红石与物流

实现自动吸起并释放铁砧的循环产线，配套完成物品搬运、过滤与存储容器。

本次核心交付包含磁铁块、空心磁铁块、雷击磁化与磁铁锭的生存获取，以及溜槽和磁力溜槽。磁铁从下方五格内吸起已落稳的原版铁砧，通电释放，断电重吸。两种溜槽提供掉落物收集、方向与过滤设置、红石暂停、向原版容器或加工台送入物品。库存、磁铁悬持与原版容器交换凭据均可保存恢复，已通过 Python 2.7 回放。尚未移植的分流器、电力收集器、木箱与后续红石元件保留在以下计划中。

简易溜槽及普通形态之间的自动转换代码已完成，覆盖高低接头、碰撞收集、单组输入、含水、冷却重载和恢复普通形态时的余物掉落。模型和贴图复用原仓库资源，侧向碰撞与含水需在客户端验收。比较器按占用槽数输出未实现，该 SDK 限制已经维护者确认。

1. 实现磁铁方块搜寻下方铁砧、吸起悬停、红石充能释放与断电重吸的状态机，同步完成铁砧锤旋转方块、拆卸机器与模式切换功能。
2. 实现铁砧砸切石机破坏下方方块、放置器放置方块和吞噬器吸收方块的逻辑，明确带库存容器、床/门双格方块与基岩等不可破坏方块的保护规则。
3. 实现溜槽、磁力溜槽、收集器、分流器、木箱与物品过滤设置，兼容原版箱子、木桶与漏斗。
4. 加入模组红石探测器、脉冲器与比较信号输出元件，验证与原版红石线路的信号传递顺序。
5. 在服务端对所有容器交互执行玩家距离、维度、方块坐标和槽位越界校验，处理目标满仓、传输途中拆除机器与存档重启恢复。

验收标准：

- 磁铁吸起、红石释放、铁砧加工、收集器拾取和溜槽入箱可以自动循环，原料消耗与入箱产物数量吻合。
- 两个相邻磁铁同时争用同一个铁砧，或原版漏斗与溜槽同时读写同一个容器时，不会复制或丢失铁砧与物品。
- 铁砧悬停期间断开红石、拆毁磁铁、卸载区块或退出重进游戏，铁砧均能恢复到确定状态。
- 满仓停机、过滤拦截、运行中拆毁和附魔/自定义数据传递测试全部通过；伪造或越界的客户端容器请求一律被服务端拒绝。

## 阶段 3：电网、流体与工业加工

上线可跨存档保存和恢复的电网、离散流体管网以及炼药锅温控加工系统。

1. 实现按维度与区块索引的电网拓扑计算，支持发电机、耗电机器、输电杆、蓄电池与电网过载断电逻辑。
2. 实现储液罐、液体泵、阀门和流体管道的离散流体网络，统一容器液体容量与传输速率单位。
3. 实现加热器、炼药锅内流体状态与温度条件判定，接入压榨、注入、固液交换、膨发、晶化、快速烹饪与高温加工配方。
4. 实现充放电机、批量合成机与批量切石机，每次工作前预检电网电量、输入原料与输出槽位余量。
5. 将机器加工阶段、内部缓存资源量和数据版本号写入方块实体扩展数据；节点方块增删或区块加载状态变化时局部更新对应网络。

验收标准：

- 电量不足停机、电力恢复续作、电网拆分与合并、区块边界卸载和存档重进后的行为符合设计预期。
- 电力与流体的产出、消耗、传输与容器余量账目一致，任何情况下容器液位和蓄电量不会溢出上限或变为负数。
- 机器加工中途退出存档或卸载区块，重新加载后原料、加工进度和产物不丢失；相邻但流体类型不同的管道不会串流。
- 在阶段 0 选定的测试设备上分别运行 1、10、100 个活动机器节点，记录服务端脚本耗时、客户端帧时间与存档保存耗时，全部控制在阶段 0 设定的性能预算内。

## 阶段 4：进阶生存与内容扩充

补齐中后期生存获取途径、装备道具、激光系统与完整引导。

1. 实现矿物涌泉、捕蟹笼、生物转化以及树脂与琥珀收集玩法。
2. 加入进阶工具、护甲、护符与恢复道具，完成移动端专用操作按键与服务端效果结算。
3. 补全高级多合锻造、珠宝加工、时移、多步加工、罐头制作，以及带容器内部数据的物品解包，逐条处理物品附加数据继承。
4. 扩展大型储存容器与筛选界面，上线通过性能验证的基础红宝石激光与棱镜折射加工。
5. 实现静态结构扫描器与建筑工具，限制单次操作体积并在放置冲突或失败时回滚；动态移动结构留在阶段 5 评估。
6. 完善游戏内手册的分类检索与生存进度提示，确保每条材料链都有清晰的获取途径与用途说明。

验收标准：

- 所有新增方块、物品与生物均完成获取途径、交互反馈、掉落返还、存档读写和多人联机测试。
- 生物转化后按白名单正确保留自定义名称、当前生命值比例、穿戴装备和驯服归属；不支持保留的属性在手册与文档中明确说明。
- 工具耐久消耗、附魔保留、容器解包物品还原准确无误，客户端快速连点不会触发服务端重复结算。
- 从新建生存存档开始完整走通一遍至阶段 4 终点的生存流程，修复过程中发现的材料断层、循环依赖和移动端 UI 遮挡问题。

## 阶段 5：复杂结构与终局玩法原型

阶段 5 的每个条目先单独制作最小验证原型并输出测试报告，验证通过且性能达标后再转入正式开发。

| 研究项 | 前置依赖 | 原型验证内容与准入条件 |
| --- | --- | --- |
| 巨型铁砧与大范围冲击 | 阶段 1 铁砧结算、阶段 3 调度 | 验证大型实体渲染、碰撞盒、大面积方块分批替换与掉落物归属，帧率与脚本耗时需在预算内 |
| 滑动导轨与推进移动结构 | 阶段 2 方块交互、阶段 4 静态结构 | 验证方块实体数据迁移、床/门等双格方块处理、实体带动、客户端动画与中断恢复，确认采用分步移动还是平滑移动 |
| 高级激光、能量武器与飞行背包 | 阶段 3 电网、阶段 4 激光与装备 | 验证长距离射线检测、高速弹射物命中、玩家飞行运动控制、伤害归属与移动端双摇杆/按键操作 |
| 超维存储与远程终端 | 阶段 2 容器、阶段 3 存档持久化 | 验证超大整数字符串编码、跨维度库存读写、多人并发访问锁与重启数据一致性 |
| 中子辐照、质量注入、空间压缩与四维多方块 | 阶段 3–4 配方、流体与结构扫描 | 验证超大体积多方块结构的扫描耗时与分步状态保存，核对全部配方数值 |
| 月球维度、类主世界、天体锻造与巨构 | 自定义维度接口、阶段 3–4 基础系统 | 验证自定义维度地形生成、重力、天空渲染、跨维度传送与存档大小，先跑通单个维度与单台天体机器 |
| 平台内部替代接口 | 模组内置手册、护符栏与电网接口 | 明确本模组自建 UI 与内部接口规范，逐项记录对上游 JEI/Curios/FE 联动的替代方案 |

每项原型完成后提交功能边界、最低引擎版本要求、存档数据结构与实测性能数据。若采用缩减版方案合入主线，需同步更新游戏内手册与仓库文档。

## 阶段 6：打包发布与回归维护

完成首发范围内全部功能的综合回归、旧存档升级校验与可重现打包。

1. 冻结首发版本的功能范围与目标客户端版本，逐一核对特性迁移矩阵、已实现配方表与测试用例。
2. 在阶段 0 确定的单人、房主联机、联机大厅与 PC/移动设备组合上执行全量回归，包含长时间自动产线挂机、弱网延迟与频繁进出存档测试。
3. 测试旧版本存档升级、存档数据版本号迁移与异常恢复流程，确保升级脚本幂等且数据无损。
4. 检查所有自定义标识符命名空间、包 UUID、依赖声明与资源路径，生成正式发布包并在干净客户端环境中导入测试。
5. 随发布包附上开源许可证、已实现功能清单、已验证客户端版本、安装升级指南与已知限制说明。
6. 归档发布版本对应的 Git 提交、SDK 依赖版本与打包步骤，持续跟踪上游 AnvilCraft 配方变更与网易 ModSDK 版本更新。

首发清单内的全部功能通过验收、无阻塞性缺陷、安装与存档升级流程正常且性能达标后即可发布。阶段 5 中暂未合入的高风险玩法继续留在后续迭代计划中。
